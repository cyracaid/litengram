# Reviewer Protocol (LitEngram v2.0)

> 用途：内部审稿人自审协议。强制跳出作者叙事，培养批判思维。
> 阅读阶段：Stage 5 · Reviewer Thinking。⛰️ 级强制，⚔️ 级可选，📌/🌫️ 跳过。
> **v2.0**：7 维度扫描仍是内部工具；但**输出写进精读时要成段落**，不用 `【反驳】`/`【疑问】` 标签。

## 目的

这不是模拟期刊审稿（不做录用决定）。目的是**在精读初稿完成后**，用一个敌对视角审视你自己的分析，找出你漏掉的漏洞。

核心追问：**"如果我不同意我自己刚写的分析，我会怎么反驳？"**

## 流程

### Step 1: 逐项过 7 个审视维度（内部扫描）

逐项扫描，每条记下"发现的攻击点 + 严重性（高/中/低）"。

| 维度 | 追问 |
|------|------|
| 1. 主要方法学隐患 | 有没有没问出来的 confound？设计是否真正回答了研究问题？ |
| 2. 未排除的替代解释 | 还有哪些可能的解释作者没排除，你也没想到？ |
| 3. 缺失的控制条件 | 有没有本该有却没有的控制组/条件？ |
| 4. 统计稳健性 | 统计是否稳健？有无 p-hacking？结果对分析选择敏感吗？按 domain 跑对应 checklist（psych 统计完整性 / nlp 评测公平性 / hybrid 双跑） |
| 5. 效度威胁 | 构念效度？内部/外部效度？nlp：指标真的测了它声称的吗？ |
| 6. 可推广性 | 能推广到目标总体吗？nlp：换语种/领域/分布还成立吗？ |
| 7. 新颖性 | 真的有新东西，还是用新方法确认已知？ |

> **NLP 域额外攻击点（domain=nlp / hybrid）**：基线同预算 tune 了吗？指标是否挑对自己有利的？只报 mean 不报显著性？训练/测试泄漏、预训练污染？人类评估的评估者数/一致性？消融完整吗？代码公开吗？

### Step 2: 写回精读（段落式，不露标签）

把站得住的攻击**写成白话段落**，落进精读的 `## 局限与批判` 与 `## 我的疑问`。

- **作者自评** → 写进"局限与批判"前半：作者承认了什么，写清为什么是局限。
- **我方反驳** → 写进"局限与批判"后半：有理由、有落点（哪一段/哪个表/哪个统计值）。
- **我方疑问** → 写进 `## 我的疑问`：指向具体段落/表/机制。
- **可执行下一步** → 写进 `## 待验证`。

**反例（禁止）：**
> - 【反驳·我方】Bonferroni 校正但未报 effect size。
> - 【疑问·我方】彩虹移动 + saccade 追逐是否混入后像。

**正例（v2.0）：**
> 我的反驳是：作者做了 Bonferroni 校正，却没有报告 effect size。这让人无法判断效应到底有多大，也无法判断校正是不是把真效应一起压掉了。
>
> 我的疑问是：彩虹图案移动加上眼跳追逐，会不会混进后像（afterimage）机制？作者没有讨论 pretext 的作用；如果彩虹本身就是一种自适应式的后像，那就必须先排除这个混淆。

### Step 3: 最脆弱结论判定

最后写一句——**"本文最经不起推敲的结论是 ___，因为 ___。"** 这比 Accept/Reject 裁决有用得多，可放进精读 `## 局限与批判` 末尾。

### Step 4（可选）: 整体印象

可附一句整体印象作参考，不作主输出：Strong Accept / Weak Accept / Borderline / Weak Reject / Strong Reject。

---

## 质量准则

- 攻击必须有具体落脚点（哪一段、哪个表、哪个统计值），不支持空泛批评
- 区分"致命缺陷"和"可改进的小问题"
- 不确定某点是否成立时，写成"我的疑问"（而非断言），并在 `## 待验证` 给出验证动作
- 扫完 7 维度都没找到站得住的攻击点，**如实写"未发现明显攻击点"**——这也是有价值的结论
