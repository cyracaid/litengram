# Literature Note Template (LitEngram v2.0)

> 用途：定义文献精读笔记的结构、内容门禁与文风。
> 阅读阶段：Stage 6 · Engram Note 时必读。
> **v2.0 重大改版**：从"12 部分压缩式 AI 摘要"改为"8 锚点展开式人类批判性阅读笔记"。
> 核心原则：精读要像人写的批判性阅读笔记，不要像 AI 标注报告。
> AI 标注、关键引用留在原文内联（Zotero），精读里不重复堆模块和标签。

---

## 一、写作哲学

**精读是写给"一个聪明但没读这篇论文的人"看的。**

读完那份精读，他应该能：
1. 说清作者在论证什么、怎么推出来的；
2. 判断证据够不够、哪一步是跳跃；
3. 知道这篇的争议点和薄弱处在哪；
4. 明白它和你自己的研究有什么关系。

为此定下五条写作原则：

1. **展开，不压缩**。每节写成连贯段落，不写关键词列表、不写电报体。一句话只放一个信息点。
2. **先解释，再评价；先理由，再结论**。术语第一次出现先用白话讲清（"可解码不等于被读出，也不等于因果"），再给英文，再说它在本文干什么。
3. **去标签**。不用 `【定义】`/`【本文角色】`/`【论证关联】`/`【延伸】`/`【反驳·我方】`/`【疑问·我方】` 这类括号字段。改成自然连接句："作者用这个概念说明……"、"我认为这里的问题是……"、"我的疑问是……"、"需要排除……"。
4. **emoji 极简**。全文只保留等级符号 `⛰️` `⚔️` `📌`。其余装饰性 emoji（🔬📘🎯🏛️🔧📊🧰📏🔗⭐📄 等）一律不用。少用方括号、少堆粗体。
5. **分工清楚**。AI 标注、关键引用、逐条批注属于**原文层**（Zotero 内联标注 / 侧注）。精读页只放批判性阅读笔记，不重复列出标注与引用清单。若担心读者找不到引用，用一句话带过："关键引用见原文内联标注。"
6. **统计模型讲设置**。论文用了统计模型（RM-ANOVA / GLM / HBM / LME / 贝叶斯 / 非参数 / PF 拟合）时，用人话讲清它**怎么搭的**——因素或设计矩阵怎么放、假设怎么处理、校正怎么做、收敛或假设违背怎么应对——不只写"用了 GLM/RM-ANOVA"。默认并进 `## 作者论证与证据`；模型是全文核心时用 `#### 统计模型怎么设的` 子标题展开。检查点清单见 `literature_analysis_framework.md` 维度 2 附。范例见第七节。

## 二、8 个锚点标题（冻结 · 机器抓取点，不再改）

```
## 基本信息
## 这篇在讲什么
## 核心论证
## 作者论证与证据
## 局限与批判
## 我的疑问
## 待验证
## 和我的研究的关系
───
## 原文摘要                ← 附录，不算锚点
```

各锚点边界：

| 锚点 | 写什么 |
|------|--------|
| 基本信息 | 论文坐标：谁做的、发在哪、什么类型、我为什么读它；元数据一行带过，不堆字段表 |
| 这篇在讲什么 | 领域已知什么 → 卡在哪 → 这篇要回答什么，一段话 |
| 核心论证 | 作者从哪个前提起、中间补了什么、得出什么结论；哪一步承重、哪一步跳跃（推理链，不是 bullet） |
| 作者论证与证据 | 主张逐条 + 证据（被试/任务/指标/数字/统计）+"够不够支撑"（见下方类型差异） |
| 局限与批判 | 作者自评（写清为什么是局限）+ 我方反驳（有理由、有落点） |
| 我的疑问 | 指向具体段落/表/机制的**不确定**——可以没有答案 |
| 待验证 | 下一步要查什么、排除什么混淆、做什么对照——**必须有可执行动作** |
| 和我的研究的关系 | 落到 research_profile.md 的具体 project/Phase：能借的方法/概念、能引的段落、能反驳的点 |
| 原文摘要 | Zotero abstractNote 原样显示，不改写（附录） |

> **`我的疑问` 与 `待验证` 的边界（防写重）**：
> `我的疑问` 写"我不确定作者为什么这么做 / 这里是不是有问题"——可以没有答案。
> `待验证` 写"下一步我要查什么、排除什么、做什么对照"——必须有可执行动作。

## 三、两类论文的内容差异（只差第 4 节写法，标题不变）

**第 4 节标题统一为 `## 作者论证与证据`**，内容按论文类型调整写法：

| | 实验 / 方法类 | 理论 / 综述类 |
|---|---|---|
| 第 4 节写法 | 主张 1 → 证据（被试 N / 任务 / 刺激 / 指标 / 结果数字 / 统计做法）→ 够不够；主张 2 … | 立场 → 论证链（前提→推论）→ 证据类型（引用/反例/直觉）→ 推理跳跃点 |
| 第 3 节 | 设计与结论之间的桥 | 前提如何推出核心命题 |

其余锚点两类共用。**不强制每篇都有全部 8 节**：若某篇确实没有对应内容（如纯理论文没有"被试"），相应内容并为段落叙述，不硬造小标题；但"核心论证 / 局限与批判 / 我的疑问 / 和我的研究的关系"通常必含。

## 四、内容门禁（替代旧结构门禁）

> 旧版检查"有没有第 7 节"。v2.0 不查小节数量，查**内容是否达标**。写入前逐条自问：

```
[ ] 不看原文，能否只从"核心论证"看懂作者怎么推出结论？
[ ] "作者论证与证据"里每条主张都配了具体证据（被试/数字/统计），不是空话？
[ ] "局限与批判"里我方批判有理由、有落点，不是"值得思考"式空话？
[ ] "我的疑问"指向具体段落/表/机制？
[ ] "待验证"给出了可执行动作？
[ ] 术语第一次出现时先有白话解释，再给英文？
[ ] "和我的研究的关系"落到了具体 project/Phase，不是泛泛"很有启发"？
[ ] 全文有没有模板标签（【定义】之类）、电报体、emoji 堆叠？（有 → 重写）
[ ] 读起来像人写的读书笔记，不像 AI 审计报告？
```

任一为否 → 重写该段，不要靠补小标题过关。

## 五、文风规则（速查）

| 要点 | 规则 |
|------|------|
| 段落 | 连贯段落，一句话一个信息点；不用电报体 |
| 术语 | 白话说清 → 英文 → 本文作用 |
| 概念 | 就地讲，不单列成"字段区"；重大概念可用 `#### 概念名` 小标题方便跳转（非必填格式） |
| 批判 | 写成"作者承认…我的反驳是…我的疑问是…待验证…"，不用 `【反驳·我方】` |
| emoji | 只留 `⛰️⚔️📌` |
| 强调 | 少量；不堆粗体、方括号、箭头 |
| 标题 | `#`/`##`/`###`/`####`，禁用 HTML 标签（见输出兼容层） |
| 摘要 | 从 Zotero abstractNote 直接读取，原样陈列 |

## 七、示范段（模板自带范例，供对齐文风）

### 概念块示范（epiphenomenal decoding）

**反例（旧版，禁止）：**
> 【定义】epiphenomenal decoding：可解码 ≠ 被读出/因果相关。【本文角色】全文逻辑枢纽。【论证关联】为 ECS causal test 铺路。【延伸】对 MVPA/解码是硬提醒。

**正例（v2.0）：**

#### epiphenomenal decoding（幽灵式解码）

这是在说：某条信息能从神经活动里被解码出来，不等于大脑真的把它读出来了，更不等于它跟行为有因果关系。比如分类器能从 fMRI 模式预测你看到的是一张脸，这只说明"脸"的信息在脑活动里留了痕迹——不代表下游区域真的用这个痕迹去识别脸，也不代表它和你的判断有因果。

作者拿这个概念当全文的转折点：现有研究大多只证明了"可解码"，所以还不能推出 ECS 有因果作用；要证明因果，后面必须做 causal test。它实际上在"可解码"和"因果相关"之间划了一条线。

对 MVPA / 解码类研究也是个提醒：解码精度高，不等于行为因果。打个比方——监控里能看出门口有人晃过（可解码），不代表门真的"认出"了他，更不代表他影响了屋里的决定（因果）。

### 局限与批判示范

**反例（旧版，禁止）：**
> - 作者自认：N=1 单被试；trial 数少；off-manifold 扰动异于自然编码。
> - 【反驳·我方】Bonferroni 校正但未报 effect size。
> - 【疑问·我方】彩虹移动 + saccade 追逐是否混入后像。

**正例（v2.0）：**

作者自己承认了几条限制。第一，这是 N=1 的单被试研究，试次数也少，从临床角度看外部效度有限——一个被试的结果推不到群体。第二，作者说如果做更广泛的 psychophysics，可能会发现更小的效应；但这个效应必须小到被试察觉不到，否则会破坏实验逻辑——被试一旦感觉到扰动，任务就不再是"无意识"的了。第三，off-manifold 扰动和自然编码不是一回事，不能直接当作自然视觉。

我的反驳是：作者做了 Bonferroni 校正，却没有报告 effect size。这让人无法判断效应到底有多大，也无法判断校正是不是把真效应一起压掉了。

我的疑问是：彩虹图案移动加上眼跳追逐，会不会混进后像（afterimage）机制？作者没有讨论 pretext 的作用；如果彩虹本身就是一种自适应式的后像，那就必须先排除这个混淆，否则所谓"神经解码"可能混入了后像带来的低层视觉反应。要验证这一点，下一步可以做一个不做注视移动的对照，或者把后像强度作为协变量测进来。

### 统计模型设置示范（LME）

**反例（禁止）：**
> 用了线性混合效应模型，条件显著，p<.05。

**正例（v2.0）：**

这篇用的是线性混合效应模型。它把"条件"放进固定效应——也就是作者真正关心的差异；同时给每个被试和每个刺激各留一个随机截距，因为同一个被试的多次反应彼此相关，不这样处理会把"被试间差异"误当成条件效应。作者先试着拟合随机斜率（让条件效应在被试间也能浮动），但模型不收敛，于是去掉随机斜率、只保留随机截距，并在附录里说明了理由。p 值用的是 Satterthwaite 近似的自由度。我注意到它没有报告随机效应的方差成分，这让读者难以判断被试之间的差异到底有多大。

|----------|---------|----------|
| ⛰️镇山之宝 | 完整精读（8 锚点全展开，含批判与疑问） | 全文关键术语都白话解释 |

## 九、输出兼容层

LitEngram 笔记需同时适配三目标：

| 目标 | 格式 |
|------|------|
| 本地 `.md` | 纯 Markdown |
| Zotero 子笔记 | Markdown → HTML 转换（写入时脚本转） |
| Notion | Markdown → Notion blocks（脚本自动转） |

**Markdown 是唯一源格式。** 笔记主体始终纯 Markdown，不嵌原始 HTML；转换在 Stage 7 写入时由脚本完成。

### 写入规则

| 要点 | 规则 |
|------|------|
| 标题 | `#`/`##`/`###`/`####` — 禁用 `<h1>`-`<h4>` |
| 加粗/斜体 | `**bold**` `*italic*` — 禁用 `<strong>` `<em>` |
| 段落 | 纯文本换行 — 禁用 `<p>` |
| 列表 | `- item` — 禁用 `<ul>` `<li>` |
| 概念块 | 可就地用 `####` 小标题 + 平铺 Markdown（可选）；禁用 `>` 引用块包裹 |
| 辨析表 | 标准 Markdown 表格（仅当并排对比真的更清楚时才用，别滥用） |
| 引用原文 | 简短 `>` 引用，不多行嵌套 |
| 代码/公式 | `` `code` `` |

### HTML 渲染（Zotero 子笔记专用）

Stage 7 写入 Zotero 时，Markdown → HTML：`##`→`<h2>`、`###`→`<h3>`、`####`→`<h4>`、表格→`<table>`、`**bold**`→`<strong>`、块引用→`<blockquote>`。此 HTML 是 Zotero 专用生成产物，**不改源 Markdown 去适配它**。

## 十、Zotero 摘要读取机制

`原文摘要` 节的来源：
1. 通过 Zotero API 或 SQLite 读取条目 `abstractNote` 字段；
2. 原样显示，不重新生成、不改写；
3. 若为空，写：`Zotero 条目未存摘要。`

禁止从 LLM 记忆或全文搜索重新生成摘要——原文摘要只需原样陈列。
