# Literature Note Template (LitEngram v1.1)

> 用途：12 部分笔记模板，定义每篇文献笔记必须包含的内容和格式。
> 阅读阶段：Stage 6 · Engram Note 时必读。
> **v1.1.1 更新**：深挖块内联嵌入对应部分、摘要从 Zotero 字段读取、HTML 渲染规范、新增 📎 关键引用节、硬门禁（每节/子节不可省）。

## 12 个必须部分（每节/子节均不可省）

每份阅读笔记必须包含以下 12 个部分。若某节在论文中无对应内容（如 Review/Theory 无"被试"），写出该节标题 + 一句"本文为综述/理论文，无此项"，而不是整节消失。

```
### 📋 基本信息
### 📚 研究背景
  · 已知 (Known)               【必填】
  · 知识缺口 (Knowledge Gap)   【必填】
  · 研究目标 (Aim)             【必填】
### 🧠 理论背景
  · 核心理论框架               【必填】
  · 关键概念（深挖）           【必填】
  · 理论→本研究逻辑链          【必填】
### 📎 关键引用          【必填 · v1.1.1 新增】

每条写：作者 (年份) + 角色符号 → 一句话（这是什么 + 溯源）→ 本文为什么依赖它。

角色符号：
- 🏛️ 理论基石 — 本文的理论框架/概念定义来自它
- 🎯 批判靶子 — 本文要改进/反驳/指出其局限的对象
- 🔧 方法来源 — 本文借用了它的范式/量表/统计/任务
- 📊 数据支撑 — 本文引它的实证结果作为证据
- 🧰 实现来源 — 我复用它代码/模型/权重/数据/工具（nlp/hybrid 常用）

引用格式：期刊论文写 作者 (年份, 期刊)；arXiv 论文写 作者 (年份, arXiv:XXXX.XXXXX)。

数量：⛰️ 6-10 条 / ⚔️ 4-6 条 / 📌 2-3 条。只收承重引用（撑起论证或方法的），不收礼节性罗列。

```markdown
- **Garfinkel et al. (2015)** 🏛️理论基石
  内感受三维模型的原始出处。
  → 本文整个测量框架建立在这三维之上。

- **Schandry (1981)** 🎯批判靶子 / 🔧方法来源
  心跳计数任务(HCT)的原始范式。
  → 本文既借它当起点，又批判它的测量学效度问题。

- **Caspi et al. (2014)** 🏛️理论基石
  精神病理学 P 因子的原始文献。
   → 本文用它论证内感受障碍的跨诊断性质。

- **Raffel et al. (2020, arXiv:1910.10683)** 🧰实现来源
  T5 架构 + C4 语料库。
  → 本文直接复用其预训练模型与微调范式。
```

### 📌 关键标注          【必填 · v1.2 新增】
### 🔬 研究方法          【domain 分发：psych 版 / nlp 版 / hybrid 双版全量】
  · psych 版: 被试 / 实验设计 / 流程 / 数据分析  【各子节必填】
  · nlp 版: 任务 / 数据 / 架构 / 训练 / 评测 + AI 实验设计检查点  【各子节必填】
### 💡 核心发现
  · 主要发现 / 理论意义 / 局限          【必填】
### 📏 复现性          【必填 · 全类型】
### 🔗 与你领域的关系           【必填】
### ⭐ 为什么这篇重要            【必填】
### 📄 原文摘要                 【必填，源为空则注明】
```

> **深挖块内联嵌入在所属节里，不得因为某个概念挖得长就跳过后面的节。**

## 完整模板

```markdown
# 📖 [主题领域] 文献精读 — [日期]

## 关键词: [3-5 个核心关键词]

## [论文完整标题]

### 📋 基本信息

- **重要等级**: {⛰️镇山之宝 / ⚔️精兵强将 / 📌补充参考}
- **论文类型**: {Theory / Methods / Empirical / Review / Benchmark / Replication / Position / Dataset / System}
- **domain**: {psych / nlp / hybrid / review-theory}
- **阅读策略**: {Deep / Standard / Fast}
- **第一作者**: [姓名] | [机构] | [实验室]
- **通讯作者**: [姓名]
- **发表**: [年份] | [期刊]
- **venue 详情**: {ACL/EMNLP/NAACL Long·Short / Findings / Best Paper / arXiv 版本号}（nlp 域填）
- **DOI**: [doi]  /  **arXiv**: {arXiv:XXXX.XXXXX}（无 DOI 时）
- **代码**: {官方 repo URL / 非官方 / 无} | **数据集**: {名称 / license / 公开性}（nlp 域填）
- **Zotero**: `itemKey` | **PDF**: `attachmentKey` | **笔记**: `noteKey`
- **引用**: ~[次数]

### 📚 研究背景

**已知 (Known)**

- 领域内已有的关键发现 2-3 点
- 承重术语就地深挖（按 concept_excavation.md 规格）

**知识缺口 (Knowledge Gap)**

- Known Knowns：领域共识但本文未涉及
- Known Unknowns：公认的未解问题
- Unknown Unknowns：本文揭示的新方向

**研究目标 (Research Aim)**

- 本文要解决的具体问题（一句话）

### 🧠 理论背景 ← 深挖密度最高的区域

**核心理论框架 (Theoretical Framework)**

- 核心理论名称 + **溯源文献** + 核心主张
- 每个框架就地挖掘（名称/提出者/年份/核心主张/在本文角色）

**关键概念 (Key Constructs)**

- 逐个按 concept_excavation.md 的 9 层规格深挖
- **易混概念并排辨析表**（如 IU vs GAD、MCC/ACC/PCC、interoception/proprioception/exteroception）
- 关键结论可加 📘/🔬 标记

**理论→本研究的逻辑链 (Rationale)**

- 用箭头展示理论如何推导出研究假设

#### 概念挖掘块格式（内联嵌入，不堆末尾）

每个概念的 9 层深挖使用 `####` 四级标题 + 平铺 Markdown 段落，不使用 `>` 引用块：

```
#### 概念名称 (English Term) 🔬

**一句话粗暴定义**：...

**溯源**：提出者 (年份, 期刊) ...

**易混辨析**：

| 概念 A | 概念 B | 区别 |
|--------|--------|------|
| ... | ... | ... |

**核心机制**：...
**在本文中的角色**：...
**与你研究的关联**：...
**人话类比**：...

**一句话总结**：**...**
```

### 📎 关键引用 (Key References)

📍 位置：🧠 理论背景之后、🔬 研究方法之前。

每条关键引用写：作者 (年份) + 角色符号 → 一句话（这是什么 + 溯源）→ 本文为什么依赖它。

角色符号：
- 🏛️ 理论基石 — 本文的理论框架/概念定义来自它
- 🎯 批判靶子 — 本文要改进/反驳/指出其局限的对象
- 🔧 方法来源 — 本文借用了它的范式/量表/统计/任务
- 📊 数据支撑 — 本文引它的实证结果作为证据

数量：⛰️ 6-10 条 / ⚔️ 4-6 条 / 📌 2-3 条。只收承重引用，不收礼节性罗列。

```markdown
- **Garfinkel et al. (2015)** 🏛️理论基石
  内感受三维模型的原始出处。
  → 本文整个测量框架建立在这三维之上。

- **Schandry (1981)** 🎯批判靶子 / 🔧方法来源
  心跳计数任务(HCT)的原始范式。
  → 本文既借它当起点，又批判它的测量学效度问题。

- **Desmedt et al. (2018)** 📊数据支撑
  实证发现 HCT 掺入非内感受过程。
  → 本文引它替 CARED 的必要性铺路。

- **Murphy et al. (2020)** 🏛️理论基石
  内感受 2×2 因子结构模型。
  → 本文是这个模型的实证检验。
```

> 每条的"这是什么"若含用户可能不懂的术语，可就地挂一个精简概念挖掘块（一句粗暴定义 + 溯源 + 人话类比）——但保持简洁，不让本节喧宾夺主。

### 📌 关键标注 (AI Annotation Highlights)

| # | 原文 | 区域 | 批注 |
|---|------|------|------|
| 1 | "...exact PDF text from Introduction..." | Intro | 【定义】... 【本文角色】... 【论证关联】... 【延伸】... |
| 2 | "...exact PDF text from Methods..." | Methods | ... |
| ... | ... | ... | ... |

覆盖区域: Intro (5条) / Methods (7条) / Results (4条) / Discussion (4条)

> 本节由 Stage 4-5 生成。若论文已有用户划线，AI 补充 ~10 条；若无划线，AI 生成 ~20 条。
> 每条批注 ~80-150 字，含 4 层结构（定义/本文角色/论证关联/批判延伸）。

### 🔬 研究方法

> 按 `paper.domain` 选版本：
> - `psych` → 只用「psych 版」子节
> - `nlp` → 只用「nlp 版」子节
> - `hybrid` → 两版子节全量并行呈现（认知NLP / LLM心理学评估 / 行为+AI 混合论文）
> - `review-theory` → 走「论证结构」版：主张链条→证据类型→推理跳跃点

**psych 版**

**被试 (Participants):** N, 性别, 年龄, 排除标准

**实验设计 (Experimental Design):** 范式+变量+结构

**实验流程 (Procedure):** 分阶段

**数据分析 (Data Analysis):** 统计方法+关键参数+软件

**nlp 版**

**任务定义 (Task):** 输入→输出形式化, 目标（分类/生成/检索/...）

**数据集 (Data):** 名称, size/split/domain, license, 是否公开, 采样/过滤策略, 是否避免测试集污染

**模型架构 (Architecture):** 预训练基座 + 新组件/微调方式（全参/LoRA/Adapter/...），模型规模

**训练细节 (Training):** batch/LR/epochs/优化器/seed 数/GPU 卡时, 温度/beam 等解码设置, few-shot shots 数 / prompt 模板数

**评测 (Evaluation):** 指标 + 为什么选它 + 对比基线 + 显著性检验 + 多次运行

**AI 实验设计检查点 (Experiment Design):**
```
· 控制变量：每次只动一个组件？还是多变量一起改
· 数据构建：采样/去重/过滤/license 是否交代清楚
· 消融设计：每个新组件都有独立消融？按维度消融还是一次全消
· 解码/超参：temperature/beam/seed 数、few-shot shots 数、prompt 模板多套取均值还是单套
· 评测设计：指标选择理由、显著性检验方法、多次 seed 取均值还是单次
· 基线公平：基线是否同预算 tune 过、参数是否公平
· 人类评估：评估者数 / 标注指导语 / 一致性 (kappa/ICC)
```

> **WHY 分析（层 2）**：解释关键设计决策背后的理由。
> psych: 为什么选这个被试数？为什么用这个设计？为什么用这个统计方法？
> nlp: 为什么用这个模型/基座？为什么选这些指标？为什么这个数据规模/split？
>
> **检查清单（按 domain 分发，见 literature_analysis_framework.md）**：psych → 统计完整性；nlp → 评测公平性；hybrid → 双跑。
> 缺失项及严重性评估：
>
> **方法学术语就地深挖**：psych 如 gPPI / MLM / bi-factor；nlp 如 LoRA / RLHF / in-context learning，按 concept_excavation.md 规格展开，附人话类比。

> **论文类型适配**：
> - Review / Theory / Position / Dataset / System：跳过方法三层拆解，改拆论证结构（主张链条→证据类型→推理跳跃点）
> - Dataset/System 论文补：发布规模 / 质量控制 / license / 更新维护
> - 任何类型缺某子节（如 Review 无"被试"）→ 写该节标题 + 一句"本文为综述/理论文，无此项"，而非整节消失。

### 💡 核心发现

**主要发现 (Main Findings):** 按重要性排序 2-4 个结果

每个发现标注：
- **证据强度**: {Direct / Indirect / Unsupported}
- **证据来源**: {Empirical / Simulation / Theoretical / Review / Benchmark / Human Eval / Ablation}
- 关键结论可加 📘/🔬 标记

**性能对比（nlp/hybrid 域）**：对每个核心 NLP 发现补一行对比

| 设置 | Score | 说明 |
|------|-------|------|
| SOTA | ... | 榜单/同期最优 |
| 本文 | ... | 论文报告值 |
| 强基线 | ... | 最强基线（同预算 tune 过？）|
| 差异 | ... | 是否进入显著性（还是仅 mean 差）|

**理论意义 (Theoretical Implications):** 支持/挑战/修正了什么理论

**局限性 (Limitations):** 作者自评 + 你的批判性评估

> 对每个核心发现的统计方法做合理性检查（psych 域）；对每个核心发现检查评测公平性（nlp 域）。

### 📏 复现性 (Reproducibility) 【全类型必填】

对论文的可复现性做现实评估——这是从"读过"到"能落地"的分水岭。psych 论文对应当前对应统计清单里的 open data 项；nlp 论文额外覆盖模型/算力/污染。

```
**代码**: {官方公开 / 非官方 / 随文发布 / 无}
**数据**: {公开 / 需申请 / 闭源} + license（nlp 域重点）
**算力**: {训练所需 GPU/卡时；我的机器能否复现——显存/预算门槛}
**复现核对**: {论文报告数字 vs 社区复现数字；差多少；哪一步最可能翻车}
**种子/超参**: {seed 数、随机性来源、是否报方差}
**接口可用性**: {能否直接加载/调用（hf hub / 现成包 / 需自己训）}
```

> 判断门槛：**"如果我要用它的方法/模型，最贵的一步是什么？"** 写下来。
> nlp 域必须落一次账：租卡/买数据/自己训 vs 直接下载权重——成本量级差距巨大，不能一笔带过。

### 🔗 与你领域的关系

- 这篇论文如何对齐你的研究方向
- **必须落到 research_profile.md 里的具体项目/Phase**
- 你可以借用的具体方法/概念（战略嫁接）
- 可引用的引述段落（英文）

### ⭐ 为什么这篇重要

简要说明本文在你的研究版图中的战略价值。

### 📄 原文摘要

> 从 Zotero 条目 abstractNote 字段直接读取，原样显示，不重新生成、不改写。
> （若 Zotero 条目未存摘要，此处写：*Zotero 条目未存摘要。*）
```

## 输出兼容层（Output Compatibility Layer）

LitEngram 的笔记需同时适配三个目标：

| 目标 | 格式要求 |
|------|----------|
| 本地 `.md` 文件 | 纯 Markdown |
| Zotero 子笔记 | Markdown → HTML 转换（写入时转） |
| Notion | Markdown → Notion API blocks（脚本自动转） |

### 核心原则

**Markdown 是所有目标的源格式。** 笔记主体始终用纯 Markdown 书写，不嵌入原始 HTML。Zotero 和 Notion 所需的格式转换在 Stage 7 写入时由脚本自动完成。

### 写入规则

| 要点 | 规则 |
|------|------|
| 标题 | `#` / `##` / `###` / `####` — 禁止 `<h1>`-`<h4>` |
| 加粗/斜体 | `**bold**` `*italic*` — 禁止 `<strong>` `<em>` |
| 段落 | 纯文本换行 — 禁止 `<p>` `</p>` |
| 列表 | `- item` — 禁止 `<ul>` `<li>` |
| 概念深挖块 | `####` 四级标题开头，平铺 Markdown — 禁止 `>` 引用块包裹 |
| 辨析表 | 标准 Markdown 表格 — 不嵌套在引用块或列表中 |
| 引用原文 | 简短 `>` 引用，不多行嵌套 |
| 代码/公式 | `` `code` `` |

### HTML 渲染（Zotero 子笔记专用）

Zotero `itemNotes.note` 存储 HTML。Stage 7 写入时，将 Markdown 源转换为 HTML：

| 元素 | Markdown → HTML |
|------|-----------------|
| `##` 笔记标题 | `<h2>...</h2>` |
| `###` 各部分标题 | `<h3>...</h3>` |

## Zotero 摘要读取机制

📄 原文摘要节的来源逻辑：

1. 通过 Zotero API 或 SQLite 读取论文条目的 `abstractNote` 字段
2. 原样显示，不重新生成、不改写
3. 若 `abstractNote` 为空，该节写：`*Zotero 条目未存摘要。*`

> 禁止从 LLM 记忆或全文搜索重新生成摘要——原文摘要只需原样陈列。

## 写笔记原则

```
原则 1: 和自己的研究对齐。每一段话至少回答一次"So what?"
原则 2: 写英文引述段落。发现可以放进 proposal 的段落，直接摘录并标注引用位置
原则 3: 写自己的"吐槽"和追问。不同意的地方标记为【反驳】【疑问】【延伸】
原则 4: 笔记末尾必须有"行动计划"——这篇论文让我接下来做什么？
```

## 不好笔记 vs 好笔记

| 维度 | 不好 | 好 |
|------|------|----|
| 方法 | "用了 U 检验" | "为什么必须用 U 检验？溯源：Wilcoxon (1945) 秩和检验。4 个核心原因..." |
| 概念 | "自适应采样" | "自适应采样：溯源 Csikszentmihalyi (1987)。人话类比：只在停车场测 vs 高速/山路/市区都测一遍" |
| 嫁接 | "这篇文章很好" | "我的 Phase 2 可以用同样的 ROC 方法，加上情绪调节变量" |
| 摘要 | AI 重写的长摘要 | 从 Zotero abstractNote 字段直接读取，原样陈列 |
